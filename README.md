# Customer Registration

A Flask application for a custom web registration form and an actual Google Form. Both submission routes use one validator and write to the same MySQL `customers` table. MySQL assigns the ID and Flask calculates age from the date of birth.

## Run on Windows

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m flask --app app run
```

Populate `.env` with your development database settings and the application secrets. Generate each secret independently with `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Use `LOCAL_SKIP_TURNSTILE=1` for local-only development. The local-only TLS override still requires an encrypted connection and is intended for isolated MySQL test servers with autogenerated certificates. Production verifies both the database certificate and hostname.

Open `http://127.0.0.1:5000/`. The form accepts non-negative balances in INR with up to two decimal places, following the original form's currency and non-negative range. The requested MySQL `FLOAT` can round balances and has limited decimal precision, especially for larger amounts. The age calculation uses `Asia/Kolkata` by default.

## MySQL and Workbench

Use a genuine MySQL deployment offering a TLS endpoint reachable from Vercel and MySQL Workbench. [Oracle MySQL HeatWave Always Free](https://docs.oracle.com/en-us/iaas/mysql-database/doc/creating-always-free-db-system.html) requires an Oracle Cloud account and network configuration for Vercel and Workbench access. [Aiven for MySQL](https://aiven.io/docs/products/mysql/howto/mysql-free-tier-migration-options) ended new free instances in November 2026 and continues on paid plans.

1. In the hosting console, create a database and obtain the hostname, port, database name, login and provider CA certificate where applicable.
2. In MySQL Workbench, create a **Standard (TCP/IP)** connection. Enter the hostname, port and username. On the **SSL** tab select **Require and Verify Identity**, supply the provider CA file if necessary, then test the connection.
3. Select the target schema and run `sql/schema.sql` as the database administrator. It creates tables only if missing. If using an existing table, confirm `SHOW CREATE TABLE customers` reports InnoDB and exactly the required six columns, with `c_id` as an auto-increment primary key.
4. Use a dedicated application account that requires TLS. Grant it `INSERT` on `customers`, `SELECT, INSERT, UPDATE` on `customer_submissions` and `SELECT, INSERT, UPDATE, DELETE` on `customer_rate_limits`. Use your administrator or a separate read-only login for Workbench inspection.
5. For production, put private CA PEM text in the Vercel environment variable `MYSQL_SSL_CA_PEM`. For Workbench keep the provider CA as a local file. Consider an export/import into an empty cloud schema if you later need a copy of local data. Review the export scope and keep existing data backed up before importing.

`customer_submissions` stores hashed submission keys and keyed fingerprints. Its transaction commits the customer and receipt together. Retries reuse the same source and idempotency key. A new registration is a new attempt, so different Google responses or attempts across the two forms can legitimately create separate records. Keep `SUBMISSION_FINGERPRINT_SECRET` stable to preserve replay verification. Rate limits use MySQL counters shared by all serverless instances. The counter keys conceal client IP addresses with a keyed hash.

## Vercel and GitHub

1. Push the Git repository to a private GitHub repository, then import it into Vercel or connect it to the existing Vercel project. The [official Flask integration](https://vercel.com/docs/frameworks/backend/flask) discovers `app.py` and serves assets from `public/`. The Vercel Hobby plan applies to personal, non-commercial projects.
2. Add the MySQL settings, `RATE_LIMIT_SECRET`, `SUBMISSION_FINGERPRINT_SECRET` and `GOOGLE_WEBHOOK_SECRET` to the Vercel **Production** environment.
3. Create a [Cloudflare Turnstile widget](https://developers.cloudflare.com/turnstile/get-started/) for the production hostname. Add `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY` and `TURNSTILE_HOSTNAME` in Vercel. The hostname should be the bare hostname where respondents open the form.
4. Deploy to production, then follow [Google Forms setup](google_apps_script/SETUP.md) with the public Vercel origin. Set `GOOGLE_FORM_URL` and redeploy.
5. Use a private browsing window to test both public form links. Submit synthetic data through each form. Confirm the generated ID in the custom form, inspect the two corresponding test rows in Workbench and confirm retrying the same request does not add another row. `/api/health` reports application liveness only.

## Tests

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

The integration test is opt-in. Use an isolated test-only MySQL database named `customer_registration_test`, point the MySQL environment variables to it, and set `RUN_MYSQL_INTEGRATION=1` before running the suite. It leaves its synthetic rows in that database. Set `LOCAL_MYSQL_ALLOW_UNVERIFIED_TLS=1` only if the test instance uses an autogenerated self-signed certificate.
